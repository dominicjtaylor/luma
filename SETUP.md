# Luma — Setup & Build Guide

---

## Prerequisites

| Tool | Requirement |
|------|-------------|
| Node.js | 18 or later |
| Xcode | 15 or later |
| CocoaPods | 1.13 or later |
| iPhone | iPhone 14 Pro / 15 / 16 series — Dynamic Island required |
| iOS on device | 16.1 or later |
| Apple Developer account | Free account works for device builds |

---

## Step 1 — Install JavaScript dependencies

```bash
cd luma
npm install
```

---

## Step 2 — Generate the native iOS project

```bash
npx expo prebuild --platform ios --clean
```

This creates `ios/luma.xcworkspace` and all generated Xcode project files.

**Important:** Do not run `expo prebuild` again after completing the Xcode steps below — it will overwrite manual changes.

---

## Step 3 — Install CocoaPods

```bash
cd ios && pod install && cd ..
```

---

## Step 4 — Open the workspace

Always open the workspace, not the `.xcodeproj`:

```bash
open ios/luma.xcworkspace
```

---

## Step 5 — Configure the main app target

### 5a — Set the bridging header

1. Select the **luma** project in the Navigator → **luma** target → **Build Settings**
2. Search: `Objective-C Bridging Header`
3. Set the value to:
   ```
   luma/luma-Bridging-Header.h
   ```

### 5b — Add native module source files

Right-click the **luma** group in the Navigator → **Add Files to "luma"**.

Add these files — target membership: **luma only**:
- `ios/LiveActivityModule/LiveActivityModule.swift`
- `ios/LiveActivityModule/LiveActivityModule.m`

Add this file — target membership: **luma only for now** (you will add it to the widget target in Step 7):
- `ios/Shared/DoomscrollAttributes.swift`

When Xcode asks about creating a bridging header, click **Cancel** — the header already exists.

### 5c — Verify Info.plist keys

Open `ios/luma/Info.plist`. Confirm these keys are present (Expo prebuild adds them from `app.json`):

```xml
<key>NSSupportsLiveActivities</key>
<true/>
<key>NSSupportsLiveActivitiesFrequentUpdates</key>
<false/>
```

If missing, add them manually.

### 5d — Verify deployment target

**luma** target → **General** → **Minimum Deployments** → **iOS 16.1**

---

## Step 6 — Create the Widget Extension target

Live Activities require a WidgetKit extension. This cannot be auto-generated by Expo.

1. **File → New → Target**
2. Select **Widget Extension** → Next
3. Fill in:
   - **Product Name:** `DoomscrollWidget`
   - **Bundle Identifier:** `com.luma.doomscroll.widget`
   - Check **"Include Live Activity"** if the option appears
   - Uncheck **"Include Configuration App Intent"**
4. Click **Finish** → when prompted to activate the scheme, click **Activate**

---

## Step 7 — Add widget source files

Xcode generates boilerplate files in the new `DoomscrollWidget` group. Delete them — select all auto-generated `.swift` files inside `DoomscrollWidget` and delete (move to Trash).

Then add the project source files:

Right-click the `DoomscrollWidget` group → **Add Files to "luma"**.

| File | luma target | DoomscrollWidget target |
|------|:-----------:|:----------------------:|
| `ios/DoomscrollWidget/DoomscrollWidgetBundle.swift` | ☐ | ☑ |
| `ios/DoomscrollWidget/DoomscrollLiveActivity.swift` | ☐ | ☑ |
| `ios/Shared/DoomscrollAttributes.swift` | ☑ | ☑ |

To set target membership: select the file in the Navigator → in the **File Inspector** (right panel, first tab) → **Target Membership** → check the appropriate boxes.

**This is the most common source of build errors.** Double-check all three files.

---

## Step 8 — Configure the widget extension Info.plist

Option A — replace the generated plist:

Delete the auto-generated `Info.plist` from the `DoomscrollWidget` group and add `ios/DoomscrollWidget/Info.plist` (target: `DoomscrollWidget` only).

Option B — edit the generated plist:

Open the generated `DoomscrollWidget/Info.plist` and add:

```xml
<key>NSSupportsLiveActivities</key>
<true/>
```

### Widget deployment target

**DoomscrollWidget** target → **General** → **Minimum Deployments** → **iOS 16.1**

---

## Step 9 — Signing

### Main app

**luma** target → **Signing & Capabilities** → select your Team → enable **Automatically manage signing**

### Widget extension

**DoomscrollWidget** target → **Signing & Capabilities** → select the **same Team**

The widget bundle ID must be prefixed with the main app ID: `com.luma.doomscroll.widget` ✓

No additional capabilities are needed for local Live Activity updates.

---

## Step 10 — Build and run

Connect your iPhone. Select it as the run destination (not a simulator).

```bash
npx expo run:ios --device
```

Or press **⌘R** in Xcode with your device selected.

The first build takes several minutes. The app will install and launch automatically.

---

## Verification checklist

Work through these in order on a physical iPhone with Dynamic Island.

### Live Activity appears
- [ ] Tap **Start Social Mode**
- [ ] Background the app (swipe up)
- [ ] A Live Activity appears in the Dynamic Island showing 🐛 and `00:00`
- [ ] Lock the screen — the Live Activity appears on the lock screen

### Dynamic Island updates
- [ ] Wait 10 seconds — the timer updates to `00:10`
- [ ] Wait 5 minutes — emoji changes from 🐛 to 🦎 and the Dynamic Island reflects it immediately (stage change triggers immediate native update)
- [ ] While in the Dynamic Island compact view, long-press it — the expanded view shows the emoji, timer, and stage name

### Activity ends correctly
- [ ] Return to the app
- [ ] Tap **Stop**
- [ ] The Live Activity disappears from the Dynamic Island and lock screen immediately

## Troubleshooting

### `expo prebuild` fails — "Cannot find module"
Ensure `npm install` completed successfully. There should be no plugin entries in `app.json` that reference uninstalled packages.

### Build error: "Cannot find type 'DoomscrollAttributes'"
`DoomscrollAttributes.swift` is not added to the correct target. In the File Inspector, both `luma` and `DoomscrollWidget` must be checked under Target Membership.

### Build error: "'RCTPromiseResolveBlock' undeclared"
The bridging header path in Build Settings is wrong. Verify it is set exactly to `luma/luma-Bridging-Header.h` (no leading slash, relative to the project root).

### Build error: "@main attribute cannot be used in a module that contains top-level code"
The widget extension has multiple files with entry-point attributes. Ensure `@main` exists only in `DoomscrollWidgetBundle.swift` and no auto-generated entry point file was left in the target.

### Live Activity does not appear after tapping Start
1. On the device: **Settings → Face ID & Passcode → Live Activities → ON**
2. Confirm `NSSupportsLiveActivities = true` in **both** the main app and widget Info.plist
3. Check the Xcode console for a `ACTIVITIES_DISABLED` rejection error

### Live Activity appears but timer never updates
ActivityKit throttles updates when the device is in Low Power Mode. Test with Low Power Mode off (**Settings → Battery**).

### `pod install` fails
```bash
sudo gem install cocoapods
cd ios && pod install --repo-update
```

## Project structure

```
luma/
├── index.js                            RN entry point
├── app.json                            Expo config (bundle ID, deployment target, plist keys)
├── package.json
│
├── src/
│   ├── App.tsx
│   ├── store/sessionStore.ts           Zustand — isActive, elapsedSeconds, stage, tick()
│   ├── screens/HomeScreen.tsx          UI + 1s timer + throttled native updates
│   ├── native/LiveActivityModule.ts    JS wrapper + no-op stub for simulators
│   └── utils/stageUtils.ts             Stage thresholds, emojis, labels, time formatter
│
└── ios/
    ├── Shared/
    │   └── DoomscrollAttributes.swift  ActivityAttributes — BOTH targets
    ├── LiveActivityModule/
    │   ├── LiveActivityModule.swift    start / update / end — main app target only
    │   └── LiveActivityModule.m        RCT_EXTERN_MODULE bridge — main app target only
    ├── DoomscrollWidget/
    │   ├── DoomscrollWidgetBundle.swift  @main entry — DoomscrollWidget target only
    │   ├── DoomscrollLiveActivity.swift  Dynamic Island views — DoomscrollWidget target only
    │   └── Info.plist                    NSSupportsLiveActivities = true
    └── luma/
        ├── luma-Bridging-Header.h      Exposes RCT headers to Swift
        └── luma.entitlements
```

## Stage reference

| Stage | Emoji | Threshold |
|-------|-------|-----------|
| calm | 🐛 | 0 – 4:59 |
| restless | 🦎 | 5:00 – 9:59 |
| agitated | 🦂 | 10:00 – 14:59 |
| exhausted | 💀 | 15:00 + |

JS timer: every **1 second** (UI only)
Native update: every **10 seconds** or immediately on a stage change
